# Messaging Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a runnable, credential-free Flutter messaging-app foundation with clean feature boundaries, core navigation, development mock services, secure Supabase migration scripts, tests, and setup documentation.

**Architecture:** Flutter presentation is feature-first and driven by Riverpod providers; domain contracts isolate UI from implementations. GoRouter guards route users through onboarding, mock authentication, and profile setup, while configuration selects mock services until valid public Supabase configuration is supplied.

**Tech Stack:** Flutter/Dart, Riverpod, GoRouter, Supabase Flutter (not initialized without config), PostgreSQL/Supabase SQL, flutter_test.

**Spec:** `docs/superpowers/specs/2026-10-20-messaging-foundation-design.md`

## Global Constraints

- Target Android and iOS now; maintain web-compatible Dart interfaces.
- Use Flutter/Dart, Riverpod, GoRouter, Supabase Auth/Realtime/Storage-compatible contracts, Firebase-compatible notification boundaries, and WebRTC-compatible call boundaries.
- Never commit `.env`, secrets, service-role keys, Firebase private credentials, database passwords, signing keys, or TURN credentials.
- Keep RLS enabled; database authorization must not depend on the Flutter UI.
- Mock mode must be explicit and only selected when public Supabase configuration is absent.
- Do not represent unimplemented external integrations as working production functionality.
- Run `flutter analyze` and `flutter test` after every task that changes Dart code.

## Review Focus

- Missing or malformed public environment values must select mock mode without crashing app startup (Task 2).
- An unauthenticated user must be unable to navigate directly to app-shell routes (Task 5).
- A mock session without profile completion must be redirected to profile setup (Task 5).
- SQL policies must not allow non-members to select or insert another conversation’s messages (Task 8).
- A stored environment file must be ignored by Git while `.env.example` remains tracked (Task 1).

---

## File Structure

- `.gitignore`: ignores generated platform files, environment files, build output, and sensitive credentials.
- `.env.example`: lists safe public configuration variable names.
- `pubspec.yaml`: Flutter SDK constraints, packages, assets, and test dependencies.
- `lib/core/config/`: typed environment and dependency-selection configuration.
- `lib/core/errors/`: typed app failures and display mapping.
- `lib/core/theme/`: color, typography, and theme definitions.
- `lib/core/router/`: route declarations and redirect logic.
- `lib/core/services/`: contracts for future platform integrations.
- `lib/features/*/domain/`: immutable entities and repository contracts.
- `lib/features/*/data/`: deterministic development mock repositories.
- `lib/features/*/presentation/`: providers, screens, and widgets.
- `lib/shared/`: reusable UI primitives and mock fixtures.
- `supabase/migrations/`: idempotent ordered PostgreSQL migration with RLS policies and indexes.
- `test/`: unit and widget tests mirroring the feature/core layout.
- `docs/`: setup, architecture, database, realtime, notifications, and WebRTC documentation.
